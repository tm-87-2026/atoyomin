# GitHubタスクの進め方

Issueの特定と状況収集にはGitHub連携ツールを使い、リポジトリの調査・編集・ビルドにはローカル環境を使う。GitHub CLIやSSHが利用できない場合も、接続済みGitHubツールでIssue、ブランチ、ファイル、コミット、プルリクエストを操作する。使える操作が足りない場合は、実行できなかった操作と必要な情報を伝え、成功したように扱わない。

## リポジトリを特定する

1. ローカルで `git rev-parse --show-toplevel` と `git remote -v` を確認する。
2. 作業ブランチのupstreamが分かる場合は、そのremoteを優先する。remote URLから `owner/repo` を読み取り、GitHub連携ツールのリポジトリ識別子に使う。
3. remoteが複数あり対象を決められない、GitHub remoteがない、または会話に示されたリポジトリと異なる場合は、接続済みリポジトリ一覧やIssueのURLで照合する。なお曖昧さが残る場合だけ、ユーザーに対象リポジトリを尋ねる。
4. GitHub CLIや認証済みSSHが使えないときは、GitHub連携ツールで読み取りや書き込みを行う。ローカルGit操作に認証が必要なら、利用可能な認証済み手段を確認する。認証情報をファイルやログに書かない。

## 「#番号のタスクに取り組む」

1. 上記の方法でリポジトリを特定し、指定Issueの本文、状態、ラベル、担当者、コメントを取得する。Issueに関連するPR、サブIssue、本文中のIssueリンクも確認する。
2. 同じリポジトリで関連語を使ってIssueを検索し、重複や依存タスクを探す。関連するPRがあれば、説明、変更内容、レビューコメント、状態を読む。
3. ローカルの作業ツリーとブランチを確認し、`AGENTS.md`などのリポジトリ規約を読む。既存の利用者変更を保持し、Issueの目的と完了条件を実装範囲にする。
4. 作業開始時は `main` を直接変更せず、Issueごとの作業ブランチを作る。ブランチ名は既存規約に従い、規約がなければ `feat/<番号>-<短い説明>` または `docs/<番号>-<短い説明>` とする。
5. Issue本文の完了条件を満たす変更を行う。確認が必要な点があれば、独立して進められる作業を先に行い、曖昧な仕様に依存する変更だけを保留する。
6. ユーザーがIssue作業を依頼し、リポジトリ規約がプッシュを求める場合は、変更が整合した時点で作業ブランチへコミットしてプッシュする。コミットメッセージはリポジトリ規約に従う。検証を実施していない場合は、その旨を記録する。
7. PRは、ユーザーがPR作成を依頼した場合に作る。本文に変更概要、検証状況、関連Issue（適用可能なら `Closes #番号`）を記載する。マージは別操作であり、明示的な依頼がない限り行わない。

## 「新しいタスクを切る」

1. 対象リポジトリのIssueを、提案されたタイトルや主要語で検索する。必要に応じて、意味の近いIssueとクローズ済みIssueも確認する。
2. 同一または非常に近いIssueが見つかったら、リンクと違いを示し、重複Issueは作らない。別タスクとして記録する必要があるとユーザーが指定した場合に限り、新しいIssueを作成する。
3. 重複が見当たらない場合は、依頼された内容をタイトル、背景・問題、目的、受け入れ条件に整理してIssueを作成する。必要な範囲でラベルなどのメタデータを付ける。
4. スコープや完了条件が判断できない場合は、推測で要件を追加せず、Issueを作る前に不足点を確認する。

## 「PRを作成する」

1. 対象リポジトリと作業ブランチを確認し、差分、関連Issue、既存PRの有無を調べる。
2. 作業ブランチを最新のbaseブランチに合わせ、競合があれば解消して差分を確認する。未コミット変更を上書き・破棄しない。
3. PRタイトルと本文を変更内容に合わせて作成し、Issue番号が分かっていて変更で解決する場合は `Closes #番号` を含める。実行していないテストやレビューを実施済みと書かない。
4. GitHub連携ツールが作成できない場合は、ローカルの変更とブランチを保ち、失敗理由とPRを作るための次の手順を伝える。

## 操作の責務と実行条件

- このSkillは、依頼の解釈、リポジトリ・Issue特定、調査順序、重複判断、変更範囲、ユーザーへの報告を定める。GitHub APIのページング、認証、Issue作成、ブランチ・ファイル・コミット・PR操作は、利用可能なGitHub連携ツールに任せる。
- 読み取り操作は、Issue作業に必要なら実施する。
- 「新しいタスクを切る」という依頼は重複確認後のIssue作成を、「PRを作成する」という依頼はPR作成を許可する。
- Issueの実装依頼は、リポジトリ規約に沿う作業ブランチの作成、コミット、プッシュを許可する。ユーザーがローカルだけの変更を指定した場合や、規約・認証が操作を妨げる場合はリモートへ書き込まない。
- Issueのクローズ、ラベル・担当者・マイルストーンの変更、レビュー依頼、PRのマージ、ブランチ保護や設定変更は、依頼に明示されない限り実行しない。
- GitHub CLIやSSHの不在は作業停止の理由にしない。接続済み連携ツールで代替し、代替手段でも実行できない書き込みだけを未完了として明示する。
