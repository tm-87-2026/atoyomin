# 開発の進行

[開発ワークフローの正本](../../../docs/development/development-workflow.md)を読み、工程・役割・移行条件・戻り方・公開境界を判断する。このSkillは親エージェントの起動と引き継ぎの手順を扱う。

## 状態を確かめる

1. 作業ディレクトリ、Issue、ブランチ、作業ツリー、成果物の配置先を確認する。AGENTS.mdと適用規約を読む。
2. 成果物の状態・合意対象・未決事項を読み、正本の「目的と適用範囲」「工程と成果物」「引き継ぎと変更時の戻り方」から担当する工程と再開条件を判断する。非実装タスクや工程調整の合意がある場合も、正本の適用条件で進める。
3. 会話で得た合意・回答のうち、次のサブエージェントに必要な内容を成果物へ記録する。不足や矛盾は正本の戻り方に従って解消する。

## サブエージェントを起動して受け取る

1. 対象工程の入力・テンプレート・関連実装を特定し、下の例を具体的なパスと担当範囲で埋める。[要求書](../../../docs/templates/requirements.md)・[設計書](../../../docs/templates/design.md)・[TODO](../../../docs/templates/todo.md)・[完了確認書](../../../docs/templates/verification.md)から今回必要なものを指定する。
2. `spawn_agent` の `message` に開始情報を渡し、`fork_turns="none"` で新規起動する。正本の「役割とコンテキスト」に従い同時実行を避ける。機能・引数が使えなければ、正本の代替方法を相談する。
3. サブエージェントからの質問をユーザーへ仲介し、回答をサブエージェントへ渡す。サブエージェントが案・結果を返したら成果物と根拠を確認する。同工程のレビュー修正は `followup_task` で同じサブエージェントへ返せる。
4. 正本の移行条件で必要な合意を確認・記録する。次工程へ移る場合は、新しいサブエージェントを起動する。完了確認で不備が出た場合も、正本の戻り先に沿って新規サブエージェントへ渡す。
5. 完了確認結果を受けたら、正本の「完了報告と公開の境界」に沿って報告し、必要な確認で停止する。Skillの起動を公開操作の許可にしない。

## 開始情報の例

以下を担当する工程に合わせて具体化する。要求・設計の本文を要約だけで置き換えず、参照先を読ませる。

```text
作業ディレクトリ: <絶対パス>
Issue: #<番号>、ブランチ: <prefix/番号>
成果物ディレクトリ: <絶対パス>
担当する工程: <今回の工程のみ>
正本: <docs/development/development-workflow.mdの絶対パス>を読む。
入力: <今回の入力ファイル一覧>を自分で読む。
合意記録: <ファイル・節・日付・合意対象>
提案状態の資料・未決事項: <参照先。なければなし>
規約・Skill・テンプレート: <AGENTS.mdと今回適用する参照先>
調査する既存実装・設定: <参照先と調査範囲>
作成・更新するもの: <成果物・変更範囲>
完了条件: <正本の担当する工程の条件と、このタスクの対象TODO>
停止条件: 正本の不足・矛盾・変更時の戻り方に従い、依存作業を止めて親エージェントへ返す。
範囲外: 次工程、コミット・push・PR作成、GitHub等への書き込みは行わない。
返すもの: 成果物パス、変更要点、検証内容・結果と根拠、残る課題・相談事項。
```

サブエージェントとしてこのSkillを読む場合は、担当する工程だけを実施して親エージェントへ返す。合意と移行の判断は正本の役割分担に従い、自ら次工程のサブエージェントを起動しない。
