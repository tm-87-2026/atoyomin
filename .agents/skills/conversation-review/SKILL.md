# 会話ログの振り返り

対象はGitで追跡中の `docs/audit/*.jsonl` だけとし、生ログ、未追跡ファイル、記録機構の変更は扱わない。リポジトリの [GitHub API操作手順](../../../docs/development/github-api.md) を確認する。GitHubから取得できない場合は分析済みとせず、理由を伝えて停止する。

## 対象を決める

1. ページ送りでマージ済みPRをすべて取得し、headブランチ名の `/` を `-` に置き換えた値とログのstem全体を照合する。完全一致が1件のみなら対応済みとする。同名headの複数PR、変換後の衝突、対応なしは確定せず、ログごとに理由と候補を提示し、利用者に採用の可否を尋ねる。手動採用はマージの証明ではない。復旧マニフェスト等を調べて重複と確認できた復旧ログは二重に分析しない。祖先判定だけでsquash mergeや削除済みブランチを除外しない。
2. `docs/conversation-reviews/*.md` の完成レポートを読み、次の機械可読ブロックの `repository` と `path` の組を分析済みキーとする。同一レポート内の形式不正、必須項目の欠落、重複キーなどで未分析の正確性を確認できないときは通知して停止する。別のレポート間では再分析により同じキーが現れ得るため、分析済みキーとして統合する。パス変更は別キーとして通知する。
3. 対応済みと未確定の件数・理由を示し、手動採用を確認してから全件、未分析、個別選択を尋ねる。全件は対応済みと今回手動採用したものを含む。個別選択では分析済みも選べる。候補なし、選択なし、不採用、取得失敗を区別して通知する。再分析では新しいレポートを作る。
4. 対象ごとに追跡パスとSHA-256を記録し、作業中と保存直前に再確認する。変化した対象や処理が失敗した対象は完成対象に含めず、理由と再試行可能な状態を報告する。

## 分析する

権限を制限した一時ディレクトリを作り、中間ファイルをそこに保存する。成功・失敗を問わず最後に削除する。JSONLを行ごとに検証し、ログパスとsession_idの組を分析単位とする。同じセッションが複数ログに分かれている場合は別範囲とし、その関係を示す。

発言順に最大100発言かつ本文40,000文字を目安として範囲を作り、境界の前後2発言を重複させる。単一発言が40,000文字を超えたら文字位置で分割し、行番号と文字範囲を保つ。重複する根拠は統合する。分割不能、容量超過、JSONL不正、読書き・子の失敗は対象と理由を示し、部分結果を完成扱いしない。

各範囲を子エージェントに渡し、流れと根拠位置を一時ファイルへ書かせる。親は中間結果を分割して読み、セッションの見取り図を作る。次に子は担当範囲の原文、見取り図、隣接範囲の要点を読み、良かった点・改善点と根拠を別の一時ファイルへ書く。子への入力はファイルパスと担当範囲に絞り、原文や結果を会話へ大量に転記しない。子を利用できない場合は代替方法を勝手に確定せず、利用者に制約と影響を伝える。

親は結果を段階的に集約する。結果が大量なら分割集約し、各発見のログパス・session_id・行番号と必要な文字範囲を原文と照合する。推測と観測を区別し、確認できない発見を確定しない。セッションごとの内容・良かった点・改善点、横断傾向と一般的な次の行動をまとめる。

## 保存する

`docs/conversation-reviews/` に実行ごとのMarkdownを一時ファイルから原子的に保存し、既存ファイルを上書きしない。完成対象だけを以下のJSONブロックに記録する。`repository` は `owner/repo`、`path` はリポジトリ相対の追跡パスとし、`sha256` は対象確定時のハッシュとする。確定した場合だけ `pr` と `branch` を含める。手動採用では `method` を `manual` とし、`reason` に対応未確定の理由と利用者が採用した事実を記載する。自動照合では `method` を `matched` とする。

```json conversation-review-targets
{"version":1,"targets":[{"repository":"owner/repo","path":"docs/audit/example.jsonl","sha256":"<sha256>","method":"matched","pr":1,"branch":"example"}]}
```

本文に実行日時、対象の判定方法、セッションごとの内容・良かった点・改善点、横断傾向と次の行動、原文をたどれる根拠、未分析・失敗と限界を記載する。手動採用の理由と利用者による採用も記録する。
