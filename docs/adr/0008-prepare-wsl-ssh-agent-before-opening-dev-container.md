# ADR 0008: ホストのSSH認証環境の準備をコンテナ接続前の初回セットアップとする

## Status

Accepted — 2026-11-02。ADR 0007を補足する。

## Context

開発者がWSL上のコンテナからGitHubを利用できるようにしたい。[ADR 0007](0007-use-host-ssh-authentication-for-development.md)では、ホストのSSH agent（秘密鍵による認証要求を受ける常駐プログラム）をDev Containersの標準機能で転送する方針とした。

検証では、ホストでagentが動いていても、接続先をDev Containersが取得できなければ転送されなかった。ホストの環境設定を整えてから接続すると、標準転送とGitHub接続が成功した。

コンテナ起動中にホストの設定も準備する案を検討したが、その時点ではホストの環境取得がすでに始まっている。同じ起動中に設定が再取得されるかは未確認であり、初回から確実に利用できる準備方法を選ぶ必要がある。根拠と確認範囲は[検証記録](../development/wsl-ssh-agent-investigation.md)を参照する。

## Decision

ホストのSSH認証環境の準備は、開発者がコンテナ接続前に実行する初回セットアップとして提供する。コンテナの起動処理が、接続に必要なホスト設定を初めて整える構成にはしない。

コンテナへの接続では、準備済みのホスト認証環境をDev Containersの標準転送で利用する。

## Consequences

- 開発者は、初回のコンテナ接続前にホスト側でセットアップを実行する必要がある。
- コンテナ接続時の環境再取得の有無に依存せず、必要なホスト設定を事前に用意できる。
- チームで共有するセットアップと、その利用手順を保守する必要がある。
