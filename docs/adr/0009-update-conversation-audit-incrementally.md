# ADR 0009: 会話の監査ログは、記録済みの発言を残して追記する

## Status

Proposed

## Context

Codexとの会話を後から確認できるよう、ユーザーとCodexの発言を監査ログに残したい。

Codexは、会話ごとに発言やツールの実行結果などをファイルに保存している。この会話の単位を「セッション」と呼ぶ。本リポジトリでは、会話終了時にそのファイルをローカルへコピーし、ユーザーとCodexの発言だけを取り出して、ブランチごとの監査ログ（`docs/audit/`）を作っている。元のファイルとコピーはGitで共有せず、監査ログは内容を確認してGitで共有する。

これまでは、保存済みの全セッションから発言を取り出し直して、監査ログ全体を毎回作り直していた。しかし、Codexが発言を保存する形式には複数あり、読み取れない形式のファイルが1つあると、後の会話も監査ログに反映されなくなった。この更新停止がIssue #30で報告された。

また、監査ログを共有する前に、秘密情報や個人情報を伏せ字にする場合がある。元のファイルには伏せ字にする前の内容が残るため、監査ログを作り直すと、その情報を再び書き出してしまう。記録済みの発言を保ちつつ、新しい発言を追加できる更新方法が必要である。

## Decision

監査ログは全体を作り直さず、記録済みの発言を残して、新しい発言だけを追加する。

どこまで記録したかは、監査ログにあるセッションごとの発言数で判断する。例えば、あるセッションの発言が10件記録されていれば、そのセッションの元ファイルから11件目以降を追加する。まだ監査ログに含まれていない過去のセッションも取り込む。

読み取れないファイルがあっても、他のセッションの発言は追加する。反映できなかったセッションと理由はローカルの状態ファイルへ残し、会話終了時にも通知する。

前回保存したコピーと比べて、元ファイルの記録済み部分が変わっていた場合は、そのセッションの追加を止め、手動での確認を求める。また、同時に複数の更新が走っても発言が失われないよう、更新は1つずつ実行し、完成した監査ログでファイルを置き換える。

## Consequences

監査ログの既存の文面は書き直さないため、伏せ字にした情報が、その後の追記や再実行で元に戻ることを防げる。読み取れないファイルがあっても、他の会話の記録を続けられる。

一方、発言数をもとに追加を始める位置を決めるため、監査ログの行を削除したり、セッションを識別する値を変えたりすると、正しく追記できなくなる。情報を伏せるときは、行を残したまま文面を変更する必要がある。

既に発言が欠けている監査ログや、記録済み部分が変更された元ファイルは、この方法では自動修復できない。元ファイルと監査ログを照合して復旧する必要がある。
