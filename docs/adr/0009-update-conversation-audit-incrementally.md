# ADR 0009: 会話の監査ログは、記録済みの発言を残して更新する

## Status

Proposed

## Context

本リポジトリで扱う会話の記録には、次の2種類がある。

- **Codexの生ログ**：Codexが自動保存する、発言やツールの実行結果などの記録。
- **監査ログ**：生ログからユーザーとCodexの発言を取り出した、Gitで共有する記録。`docs/audit/` に保存する。

従来は、更新のたびに保存済みの生ログをすべて読み直して、監査ログを作り直していた。生ログには、従来の処理では発言を読み取れない記録方式があった。読み取りに失敗すると更新処理全体が止まるため、それ以降の会話も監査ログに反映されなくなった（Issue #30）。

監査ログをGitで共有する際は、秘密情報や個人情報を伏せ字にする場合がある。生ログはCodexが保存した元の記録として手を加えず保持するため、この編集は監査ログだけに行う。そのため、生ログから監査ログを作り直すと、伏せた情報が再び書き出されてしまう。

## Decision

記録済みの発言は更新前の監査ログから引き継ぎ、未記録の発言だけを生ログから取り込む。発言の読み取りは、従来対応していた記録方式に加え、今回読み取れなかった方式にも対応する。

一部の生ログを読み取れなくても、他の会話の取り込みは続ける。反映できなかった対象と理由を利用者へ知らせ、生ログを使って復旧できるようにする。

保存時は監査ログへ直接追記せず、全件を別ファイルへ書き出し、完成後に置き換える。書き出し中に失敗しても更新前の監査ログが残るため、次回は同じ未記録分を取り込んで再実行できる。

## Consequences

監査ログの既存の発言を引き継ぐことで、伏せ字を保持できる。また、一部の生ログを読み取れなくても、他の会話は監査ログに反映できる。

完成後に置き換える方式では、監査ログへの直接追記が中断した場合に必要となる、書きかけの最終行を修復する処理を省ける。その代わり、新しい発言が少なくても毎回全件を書き出す。

既に監査ログに欠落や誤りがある場合、通常の更新では修復しない。生ログと監査ログを照合する復旧作業が必要になる。
