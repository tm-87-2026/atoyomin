# ADR 0012: フロントエンドを機能単位で配置する

## Status

Accepted — 2026-11-17

## Context

あとよみんでは、AIと人間がコードの役割と配置を理解し、チームで一定の品質を保って変更できるようにしたい。画面の組み立て方はThinking in Reactに従うが、コードの配置方針も必要である。

配置は独自の方法を作るより、既存のプラクティスに基づいて定めたい。[Bulletproof React](https://github.com/alan2207/bulletproof-react)はAlan Alickovicが公開する設計ガイドで、機能単位の配置と依存関係の原則を説明している。

## Decision

Bulletproof Reactの配置方針を参考に、関連コードを機能単位にまとめる。機能に依存しない部品を共通部分に置き、アプリケーション全体の組み立ては `app/` が担う。

各機能は同じ機能の内部と共通部分を利用し、別機能を直接importしない。具体的な配置と判断例は[アーキテクチャドキュメント](../architecture.md)に記載する。必要なディレクトリーから作成し、状態管理やデータ取得ライブラリは実装を通じて判断する。

## Consequences

- 機能を変更するときに、関連コードを同じ場所から追える。
- 複数機能の組み合わせは `app/` に集める必要がある。
- 機能の分け方と共通化の判断には、文書の原則と具体例を用いる。
