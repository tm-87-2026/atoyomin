# ADR 0005: JavaScriptの依存関係をpnpmで管理する

## Status

Accepted — 2026-10-21

## Context

React、Vite、SupabaseのSDKなど、アプリはJavaScriptの外部パッケージに依存する。

目指す状態は、開発者とCIが同じ依存関係を再現でき、外部パッケージの更新内容を確認してから取り込めることである。さらに、インストール時に自動実行されるコードや、公開直後のパッケージによるリスクを抑えたい。

パッケージの不正な更新や、インストール時に自動実行されるスクリプトは、開発環境とCIに影響を与え得る。この状態を実現するため、依存関係の固定と、インストール時スクリプトおよび公開直後のパッケージを制限できるパッケージマネージャーが必要である。

## Decision

目指す状態を実現するため、JavaScriptのパッケージマネージャーにはpnpmを採用する。pnpmは、依存パッケージがインストール時に実行するスクリプトを個別に許可でき、新規公開から一定時間以内のパッケージとGitリポジトリやURLを参照する間接依存を制限できる。[pnpmの供給網保護機能](https://pnpm.io/)と[build scriptの許可設定](https://pnpm.io/cli/approve-builds)を確認した。

- `pnpm-lock.yaml`をコミットし、開発環境とCIではlockfileに従って依存関係を導入する。
- 依存パッケージのインストール時スクリプトは、必要性を確認したものだけを許可する。
- pnpmの`minimumReleaseAge`を1,440分（24時間）に設定し、新規公開から24時間以内のパッケージは導入しない。緊急時に例外を設ける場合は、理由をプルリクエストに残す。
- GitHubリポジトリでDependabot alertsを有効にし、GitHub Advisory Databaseに登録された既知の脆弱性と依存関係を照合して通知を受ける。修正版へ更新できる場合は、Dependabot security updatesのプルリクエストを受け取る。
- `.github/dependabot.yml`を管理し、脆弱性の有無にかかわらない通常の依存関係更新もプルリクエストとして受け取る。いずれのプルリクエストも内容を確認してから取り込む。

## Consequences

- 全員とCIが同じ依存関係を利用でき、意図しない更新を防げる。
- インストール時に実行されるコードと、新規公開直後のパッケージによるリスクを減らせる。
- 一部のパッケージは動作にインストール時スクリプトを必要とするため、導入時に許可判断が必要になる。
- 緊急の脆弱性修正や新しいパッケージの導入では、24時間の待機を例外とする判断が必要になる。
- Dependabotの脆弱性通知・セキュリティ更新には、GitHubリポジトリ側の設定が必要になる。
- Dependabotが検出できるのは、GitHub Advisory Databaseに登録された既知の脆弱性に限られる。
