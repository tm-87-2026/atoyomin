# ADR 0012: 親エージェントが成果物を介してサブエージェントを交代する

## Status

Accepted（2026-11-08、ユーザーの明示承認）。

## Context

[ADR 0011](0011-separate-development-context-by-phase.md)で決めた4フェーズの分離を、ユーザーの相談窓口を維持しながら実現したい。前工程の会話履歴に依存せず、新しいサブエージェントが合意済みの成果物から再開できる必要がある。

新しい会話へ人間が引き継ぐ方法と、対話を続けるCodex（親エージェント）が、各工程の作業を行う別のエージェント（サブエージェント）を起動する方法を検討した。後者を選び、起動・引き継ぎの人間の操作負担を抑える。同時更新と工程間の思い込みの持ち越しを避けるため、サブエージェントは順番に交代する。

## Decision

親エージェントがユーザーとの相談・合意・進行管理を担い、各工程は親エージェントの会話履歴を渡さない新規サブエージェントに依頼する。同時に動かすサブエージェントは1つとし、次工程に前のサブエージェントを再利用しない。

合意・判断理由・未決事項をMarkdown成果物へ記録し、サブエージェントは成果物と適用規約を自分で読む。親エージェントは合意記録と工程の移行条件を確認して次のサブエージェントを起動する。具体的な運用の正本は[開発ワークフロー](../development/development-workflow.md)とする。

## Consequences

ユーザーとの窓口を維持し、工程を履歴から分離して再開できる。一方、各サブエージェントが資料を読み直し、親エージェントが合意と引き継ぎ状態を記録する負担が生じる。

この構成には履歴の引き継ぎを制御できるサブエージェント機能が必要になる。利用できない環境では新しい会話への引き継ぎ方法を相談する。サブエージェントを分けても誤りの発見は保証されず、要求・差分・検証根拠の照合を続ける。
