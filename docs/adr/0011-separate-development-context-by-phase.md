# ADR 0011: 開発ワークフローのコンテキストを4フェーズに分離する

## Status

Accepted（2026-11-07、ユーザーの明示承認）

## Context

Issue #40では、Codexと人間が協働する開発ワークフローを定義している。要求と実現手段を切り分け、完了確認では実装中の思い込みに引きずられず、要求と実際の成果物を照合したい。

各工程でコンテキストを分離する案を検討した。設計とTODOの洗い出しは続けて扱う利点があり、TDD（テスト駆動開発）のテスト作成と実装も短い反復の中で連続して扱いたい。

## Decision

コンテキストを「ありたい姿のすり合わせ」「設計・TODO洗い出し」「実装・単体テスト」「完了確認」の4つに分離する。

フェーズ間では、合意済みの成果物、必要な判断理由、未解決事項を引き継ぐ。検討途中の案と決定事項を区別する。

## Consequences

要求をすり合わせるコンテキストと実現手段を考えるコンテキストを分け、完了確認も実装とは別に行う。一方、各フェーズを再開するため、成果物に合意内容と必要な判断理由を残す作業が必要になる。

コンテキストを切り替える具体的な操作と、開始情報の渡し方は別途設計する。
