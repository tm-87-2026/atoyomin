# ADR 0011: 実装を通じてアーキテクチャを具体化する

## Status

Accepted — 2026-11-17

## Context

あとよみんでは、コードの役割と変更の影響を3人が理解し、一定の品質で開発できる構成を目指す。開発は業務時間外に行い、2027年3月19日までにプロダクトバックログのStoryをすべて実装したい。

Supabaseは全員未経験で、React・TypeScriptの経験にも差がある。アプリ本体が未実装の段階で適切な構成を選ぶことは難しく、開発を始めて実際のコードから判断したい。

## Decision

特定のアーキテクチャを先に固定せず、共通の設計原則に沿って実装し、最初の動く機能ができた段階で構成を見直す。

フロントエンドはReact公式の[Thinking in React](https://react.dev/learn/thinking-in-react)に沿い、コンポーネント分割、静的な画面、最小限のstate（変化を記憶する値）、stateの配置、操作から更新への流れの順で組み立てる。

バックエンドはSupabaseの処理の流れと制約を実装で確認し、具体的な層構成や依存関係の分離を判断する。適用方針と未決定事項は[アーキテクチャドキュメント](../architecture.md)で管理する。

## Consequences

- 構成の選定だけで開発開始を遅らせず、実装を判断材料にできる。
- 初期実装の構成は、理解・変更しにくい箇所が見つかればリファクタリングする。
- 最初の動く機能をチームで確認し、必要な配置・分離のルールを文書へ反映する。
