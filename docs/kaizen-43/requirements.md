# worktree内での開始・再開の要求

## 基本情報

- 対象Issue: [#43](https://github.com/tm-87-2026/atoyomin/issues/43)
- 状態: 合意済み
- 合意日・合意対象: 2026-11-11、要求全体。ユーザーの「ok」により明示合意。

## 背景・目的

既にタスク用worktreeを開いている状態で「#27をやります」と伝えた際、task-startが再度適用され、ブランチ・worktreeの準備や別ウィンドウ起動を行う流れになった。現在のtask-startはIssue番号を伴う開始の呼びかけを広く対象とし、既存worktreeからの呼びかけも開始処理に含めている。

タスク用worktreeとは、対象Issueの作業ブランチがチェックアウトされ、作業環境として用意されたworktreeを指す。そこで同じタスクの開始・再開を依頼した場合は、開いている環境をそのまま使って開発を進めたい。元リポジトリでタスク用の環境を準備する依頼とは区別する。

今回のユーザー要望は、既に開いている `.worktrees/kaizen-43` でIssue #43に取り掛かることであり、worktreeや別ウィンドウの起動を追加で行うことではない。

## 対象範囲

### 対象

- task-startとdevelopment-workflowの適用条件、および開始・再開時の案内と手順の整合。
- タスク用worktree内で同じIssueへの開始・再開を依頼する場合の挙動。
- 元リポジトリからタスク用の環境を準備する既存手順の維持。

### 対象外

- 開発ワークフローの工程、成果物、合意・公開の境界の変更。
- ブランチ名・worktree配置先・認証設定の方式変更。
- 別Issueの作業環境への切り替えや、worktree管理機能の追加。

## 要求

### REQ-001: タスク用worktree内では現在の環境を利用する

- 対象Issueのタスク用worktree内で同じIssueへの開始・再開を依頼した場合、現在のブランチとworktreeを使って作業を進める。
- この依頼を理由に、ブランチ・worktreeの準備や別ウィンドウ起動を再実行しない。
- 「#番号に着手する」「#番号をやります」など、開始を表す言い回しだけで環境準備の依頼とは判断しない。

- タスク用worktree内で同じIssueの作業を依頼した場合、開発ワークフローに従い、現在の成果物と合意状態に応じた工程から始める。

### REQ-002: 元リポジトリからの環境準備を維持する

- 元リポジトリからタスク用の環境を準備する依頼では、既存のtask-startによるブランチ・worktree準備と別ウィンドウ起動を引き続き利用できる。
- 同じタスクのブランチ・worktreeが既にある場合に再利用する既存の扱いを維持する。

## 完了条件

- タスク用worktree内で同じIssueの開始・再開を依頼する代表例について、ブランチ・worktree準備や別ウィンドウ起動を行わず、現在の環境で開発へ進むことを確認できる。
- 成果物がない開始時と、成果物・合意記録がある再開時の両方で、開発ワークフローに沿う案内となることを確認できる。
- 元リポジトリからの環境準備について、新規作成と既存環境の再利用の両方が引き続き可能であることを確認できる。
- 関連するSkill・文書の適用条件と手順に、上記の要求と矛盾する記述が残っていない。
