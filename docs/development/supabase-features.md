# Supabaseで利用する機能と用途

## 目的と対象範囲

Supabaseの機能を利用する機能開発を計画するとき、実装済みの構成、既存の方針、未決定の事項を取り違えないために、現時点での利用状態と用途をこの資料にまとめる。対象はAuth、Database・RLS、Edge Functions、Storage、Realtimeである。この列挙は、すべての機能を採用することを意味しない。

認証方式やユーザーごとの認可、環境設定、アーキテクチャの責務分割は対象外とし、それぞれの担当タスクで扱う。

## 利用状態の記録規則

機能の利用状態は、実装済み、既存の方針で利用を予定、現時点で利用しない、今後の検討対象の4区分で記録する。実装済みはコードまたはマイグレーションで確認できる事実、既存の方針で利用を予定はAccepted ADRまたは規約で定めた方針を表す。現時点で利用しない機能は、必要となる要求が生じた時点で再検討する。今後の検討対象として記録する場合は、利用の要否を判断する担当タスクまたは条件も併記する。

今回の5機能が4区分すべてに分かれるわけではない。利用状態と根拠は次のとおりである。

| 機能           | 利用状態               | 本アプリでの用途                                    | 根拠・再検討条件または担当タスク                                                                                                                                                                                                                              |
| -------------- | ---------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Auth           | 既存の方針で利用を予定 | 利用者の認証                                        | [設計規約](../conventions/design.md)および[ADR 0002](../adr/0002-use-supabase-for-backend-services.md)の方針。認証方式、リクエストフロー、トークン、ユーザーごとのRLSは[Issue #20](https://github.com/tm-87-2026/atoyomin/issues/20)で決定する。              |
| Database・RLS  | 実装済み               | 接続確認用の`public.app_status`を読み取る           | [Supabaseクライアント](../../src/lib/supabase.ts)と[接続確認用マイグレーション](../../supabase/migrations/20261107000000_create_app_status.sql)。ブラウザは公開用キーでData APIへ接続し、RLSを有効化して`anon`と`authenticated`に`SELECT`だけを許可している。 |
| Edge Functions | 既存の方針で利用を予定 | 秘密情報を要する外部API、特権操作などのサーバー処理 | [設計規約](../conventions/design.md)および[ADR 0003](../adr/0003-use-cloudflare-pages-for-frontend-hosting.md)の方針。必要なサーバー処理の要求が生じた担当タスクで、個別処理の採否と実装詳細を検討する。                                                      |
| Storage        | 現時点で利用しない     | なし                                                | 現行実装・既存方針にファイル保存の要求はない。ファイル保存の要求が生じた担当タスクで、バケット構成とアクセス制御を含めて再検討する。                                                                                                                          |
| Realtime       | 現時点で利用しない     | なし                                                | 現行実装・既存方針にリアルタイム更新の要求はない。リアルタイム更新の要求が生じた担当タスクで、用途と利用方式を再検討する。                                                                                                                                    |

## 既存方針との整合

SupabaseはPostgreSQL、認証、必要に応じたサーバー処理を利用するバックエンドサービスとして採用している。[ADR 0002](../adr/0002-use-supabase-for-backend-services.md)は、ブラウザからデータを直接扱う場合にRLSを設計・設定する必要があることを定める。本資料はその共通方針を示すが、具体的な認可設計は定めない。

フロントエンドはCloudflare Pagesから静的配信し、初期構成にはWorkers・Pages Functionsを追加しない。サーバー処理が必要になった場合は、まずSupabaseの機能で実現できるか検討する。[ADR 0003](../adr/0003-use-cloudflare-pages-for-frontend-hosting.md)と[設計規約](../conventions/design.md)を参照する。
