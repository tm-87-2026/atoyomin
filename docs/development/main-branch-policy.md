# mainブランチの運用方針

`main`への変更を取り込む経路を揃え、意図しない直接pushを防ぐため、このリポジトリでは以下の方針で運用する。GitHubの設定状況は別途確認する必要があり、本書の記載だけで設定が有効になっていることは保証されない。

## 変更の取り込み

1. 作業ブランチで変更を行い、そのブランチをpushする。
2. `main`を取り込み先とするプルリクエスト（PR）を作成し、変更を取り込む。`main`へ直接pushしない。

コミットとPR作成の前に必要なユーザー確認は、[開発ワークフロー](development-workflow.md#完了報告と公開の境界)に従う。PRの承認は当面、取り込みの必須条件としない。

## GitHubでの制限

GitHub側でも`main`への直接pushを防ぎ、PRを経由した取り込みを必須とすることを目指す。管理者にも原則として同じ制限を適用する。設定の可否はリポジトリの管理権限や利用可能な機能を確認して判断する。設定できない場合も上記の運用方針に従うが、GitHubによる強制はない。

緊急時に通常の取り込み経路を使えない場合は、管理者が状況に応じてルールを見直す。恒常的な管理者の例外は前提としない。

強制push、ブランチ削除、CIの必須化などの追加制限は、この方針では決めていない。必要になった時点で別途検討する。
