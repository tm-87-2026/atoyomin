# 会話ログの振り返りの設計

## 基本情報

- 対象Issue: #72
- 状態: 合意済み
- 合意日・合意対象: 2026-11-27、レポート改善フィードバックを反映した文書全体。
- 正とする要求書: [requirements.md](requirements.md)

## 設計の概要

人間が最低限読む範囲は基本情報とこの節とする。後続の担当者は[詳細設計](#詳細設計)も読む。

### 全体構成

手動起動するSkillが監査ログとマージ済みPRを照合し、利用者が対象を選ぶ。ログを小さな範囲へ分割し、機械的シグナルで詳しく読む候補を示したうえで、人間の指示・判断・提案した進め方を原文と外部プラクティスに照らして読む。親は結果を統合し、「継続すべき点」「改善すべき点」を主軸とするレポートを保存する。

Codexの応答は評価対象にせず、人間の発言が何への指示・訂正・判断だったか、その作用を理解する前後関係としてだけ参照する。所見は、人間の必要最小限の引用、原文位置、単一セッションか横断傾向か、外部資料の明記・分析上の推論・不明を一まとまりで示す。

### 主要な設計判断と採用理由

- [ポイント中心のレポート](#分析とレポート構造req-002req-005)にし、利用者が行動の判断を先に読めるようにする。各所見に対象と根拠位置を付け、個別ログへ戻れるようにする。
- [外部プラクティスを版管理した評価観点として保存する](#外部プラクティスの保存と適用req-005)。実行ごとの解釈差を抑える一方、資料更新を自動追従しないため確認日と適用範囲を明記する。
- [シグナルの決定的集計とLLMによる文脈判定を分ける](#機械的シグナルとドリルダウンreq-006)。再現可能な候補抽出を優先し、意味分類が必要な事象を語句一致だけで断定しない。
- [ブランチ・ログ別ダッシュボード](#機械的シグナルとドリルダウンreq-006)を機械データの主表示にする。規模差を踏まえて件数と率・分母を並べ、正確な値を表で比較してから原文へ移れるようにする。
- [過去レポートを分析済みの正本とする](#対象の決定req-001req-003)。別台帳との不一致を避ける代わりに、レポート形式の検証が必要になる。
- [分割と二段階の読み](#大量ログの分析req-004)で一度に扱う量を抑える。初期閾値は安全上限の保証ではなく、同じ3ログで調整する値とする。

### 適用条件と運用上の制約

対象はリポジトリで追跡される `docs/audit/*.jsonl` であり、生ログ、未追跡ログ、記録機構は扱わない。GitHubのマージ済みPR情報を取得できない場合や、ログとの対応を確定できない場合は、理由を示して利用者の判断を求める。

外部プラクティスは評価対象の製品、作業、時点へ適用できる範囲だけを使う。公式資料の記述、観察研究、そこからログ評価へ当てはめる推論は証拠の性質が異なる。資料間に緊張がある場合や成果・画面操作などログ外の情報が必要な場合は、一方を採用して良否を断定せず「不明」とする。

### 成立を確認した根拠と限界

対象選択、分割、二段階分析、保存は合成ログと実ログで試行済みであり、詳細は[TODOの実施記録](todo.md#実施記録)にある。[初回レポート](../conversation-reviews/2026-11-26-kaizen-73-docs-49-env-28.md)は対象ハッシュと引用位置を確認済みだが、旧要求に基づきブランチ・セッション別を主構成とし、Codexの行動を評価した表現も含む。REQ-002、REQ-005、REQ-006の完了根拠には使えない。

親子のコンテキスト圧縮を完全に観測する手段は未確認である。圧縮イベントが見つからないことを「圧縮なし」の証拠にはしない。シグナルの意味分類と初期閾値も未検証であり、同じ3ログの再分析で誤検出・見逃しとドリルダウンへの寄与を記録する。

### 人間の判断に関わる未決事項

なし。圧縮を観測できない場合は「不明」と記録し、シグナルの閾値は試行可能な初期値として調整する。

## 詳細設計

### 成果物・変更範囲

- `.agents/skills/conversation-review/SKILL.md` を更新し、必要な決定的処理は同Skillの `scripts/` に置いて自然言語の意味分類と分離する。
- `.agents/skills/conversation-review/references/` に外部プラクティスの評価観点を保存する。
- `docs/conversation-reviews/` に実行ごとのレポートを保存する。旧レポートは上書き・修正しない。
- 監査ログや記録機構は変更しない。

### 対象の決定（REQ-001、REQ-003）

1. GitHubのマージ済みPRをページ送りして取得し、ログのstemと、PRのheadブランチ名の `/` を `-` に置換した値を完全一致で照合する。一意でない候補、変換衝突、対応なしは自動確定せず、理由と候補を示してログごとに採否を確認する。復旧用の重複ログは二重分析しない。
2. 過去レポートの機械可読な完成対象一覧から、リポジトリと追跡パスの組を分析済みキーとして読む。形式不正で未分析を正確に判定できない場合は停止する。再分析時にも同じキーを選べる。
3. 対応済み、未確定、失敗の件数と理由を示し、未確定ログの採否を確認してから、全件、未分析、個別選択を利用者へ提示する。
4. 対象確定時の追跡パスとSHA-256を記録し、保存直前に再確認する。変化・失敗した対象は完成対象に含めない。

旧レポートと再分析レポートに同じ分析済みキーがあっても正常とする。新しいレポートには再分析であることと比較した旧レポートのパスを記録するが、旧レポートを失効扱いにはしない。分析済み判定は一度でも完成した対象であることを示し、最新評価の選択までは意味しない。

### 大量ログの分析（REQ-004）

1. JSONLを行単位で検証し、ログパスと `session_id` の組を分析単位とする。根拠位置はログパス、セッションID、行番号、必要な場合は文字範囲で表す。
2. 初期値として1範囲を最大100発言かつ本文40,000文字とし、境界の前後2発言を重ねる。単一発言が上限を超えた場合は文字位置で分割する。この値はトークン上限や品質を保証する閾値ではない。
3. 子が各範囲の人間の行動、流れ、根拠候補を一時ファイルへ出力し、親が見取り図を作る。子は原文、見取り図、隣接範囲の要点、シグナル候補を再読して所見候補を出す。
4. 親は中間結果を段階的に集約し、所見ごとの原文を再確認する。大量の中間結果も分割して扱う。
5. 一時ファイルはアクセスを制限した一時ディレクトリに置き、成功・失敗時に削除する。子の失敗、JSONL不正、読取・書込失敗、分割不能、容量超過は部分的な完成として保存しない。

### 機械的シグナルとドリルダウン（REQ-006）

シグナルは、ブランチ・ログ間の違いから詳しく読む対象を発見するための情報である。機械データの冒頭では、初見の読者向けに各シグナルの意味と探索用途を次のように説明する。抽出上の注意は所見ごとに繰り返さず、方法または限界へまとめる。

| シグナル | 何を数えるか | 値から何を探せるか |
| --- | --- | --- |
| ラリー | 人間とCodexの完了した往復 | 共同検討や調査が長く続いたログ・セッション |
| 訂正・介入 | 人間が直前までの方針・事実・実行を止める、戻す、否定する、変更する発言候補と文脈上の採用 | 人間が進行を立て直した箇所や、同じ論点で介入が続いた範囲 |
| 確認質問 | Codexが人間の選択・情報・許可を待った質問候補と文脈上の採用 | 判断待ちや情報不足で作業が止まった箇所 |
| 人間の指示の反復 | 同じ目的・制約・訂正を人間が再度伝えた発言 | 制約が伝わらず再提示された可能性のある論点 |
| セッションの長大化 | セッション別の発言数、本文文字数、ラリー数 | 合意や話題の境界を詳しく確認する長いセッション |

機械データの主表示は、1行をブランチまたはログとするMarkdown表のダッシュボードにする。全体合計は表の末尾または直後の補助情報とし、合計だけを主表示にしない。少なくとも次の列を置き、読者の比較、判断、ドリルダウンに使わない実行管理列は置かない。

| 列 | 表示内容と判断への用途 |
| --- | --- |
| ブランチ・ログ | 比較単位。追跡パスを併記する |
| セッション数・人間発言数 | 件数の規模を解釈する分母 |
| ラリー | 件数と1セッション当たりの値 |
| 訂正・介入 | 機械候補数、文脈上の採用数、採用数／人間発言数 |
| 確認質問 | 機械候補数、文脈上の採用数、採用数／Codex発言数 |
| 反復 | 採用した反復数、採用数／人間発言数 |
| 長大化 | 該当セッション数／全セッション数と、最長セッションの発言数・文字数 |
| 読む入口 | 優先して読むsession_id・行範囲と、そこから探せること |

率は分子と分母が分かる `採用数/分母（割合）` の形で示し、取得不能と判定不能を0へ置き換えない。少数のログやセッションでは偶然の影響が大きいため、比較は探索順の決定に使い、順位や優劣を結論にしない。

比較グラフは必須とし、少なくともブランチ・ログ別ラリー数を並べる。率や長大化も比較に価値がある場合は、件数と率を同じ軸へ混在させず別のグラフにする。表示互換性と正確な値を優先し、Markdown表を正本、グラフを補助とする。Mermaid `xychart-beta` の対応を確認できない場合は、通常のMarkdownで崩れない等幅コードブロックの横棒グラフを使い、棒の末尾に正確な値を併記する。

初版で扱う候補と定義を次に示す。初期値は同じ3ログで有用性を試す値であり、良否の基準ではない。

| シグナル | 初版の算出 | 機械抽出とLLM判定 | ドリルダウンと限界 |
| --- | --- | --- | --- |
| ラリー数 | 人間発言の後にCodex発言が現れる完了した往復を1と数える。連続する同一話者の発言は一まとまりとする | 話者と順序から決定的に集計する | 往復の多いセッションを読む。長い調査や共同検討でも増える |
| 訂正・介入 | 人間発言のうち、直前までの方針・事実・実行を止める、戻す、否定する、または変更するものを候補化し、人間発言まとまり数に対する採用数も示す | 否定・中止等の表層語は機械候補、最終分類と対象はLLMが前後を読む | 同じ論点への介入が連なる範囲を読む。追加情報や通常の要望を誤検出し得る |
| 確認質問 | Codex発言のうち、人間の選択・情報・許可を求め、回答待ちになる質問を数え、Codex発言まとまり数に対する採用数を頻度として示す | 疑問符等は機械候補、修辞疑問・自己確認を除く分類はLLMが行う | 質問が集中する開始部や停止点を読む。必要な安全確認も含む |
| 人間の指示の反復 | 正規化後の完全一致を機械候補とし、同じ目的・制約・訂正を改めて伝えた発言を意味上の反復とする | 完全一致は決定的、言い換えと同一論点はLLM判定。根拠位置を残す | 反復された論点と間の応答を読む。定型承認、引用、別対象への同じ手順を誤検出し得る |
| セッションの長大化 | 発言数、本文文字数、ラリー数をセッション別に集計する | 決定的に集計する | 初期候補は100発言または40,000文字以上、および対象内の上位セッション。長さだけで非効率としない |

機械候補とLLMの採否が異なる場合は候補数と採用数を分ける。判定できない候補はゼロにせず「判定不能」とする。各所見は値から生成せず、候補範囲の原文を読んだ結果として作る。シグナルに現れない継続すべき点も通常の範囲分析から拾う。

### 外部プラクティスの保存と適用（REQ-005）

評価観点のスナップショットは、資料名、提供組織、URL、確認日、資料に明記された推奨と理由、製品・機能・タスク種別の適用範囲を保存する。ログ上で探す兆候は資料の明記ではなく分析へ適用する推論として分ける。観察研究か実践ガイドか、因果を示すか、ログだけでは分からない事項、資料間の違いも記録する。

実行時はスナップショットを既定の根拠として読み、所見へ観点IDと出典URLを付ける。原典の現行性が評価を左右する場合だけ公式ページを再確認する。特定製品の推奨を他製品へ当てはめる場合は「推論」と明記する。資料同士が異なる、観察研究しかない、ログ外の成果が必要、人間とCodexのどちらが原因か分離できない場合は「不明」とする。外部資料は所見を探す観点であり、チェック項目の有無だけで採点するルーブリックにはしない。

### 分析とレポート構造（REQ-002、REQ-005）

各範囲では人間発言を起点に、指示、判断、進め方の提案を識別する。Codex発言は、人間が何に反応し、介入が何を変えたかを理解するために必要な最小範囲だけ読む。Codexの正確性、丁寧さ、実装品質を所見の主語にしない。人間の意図や成果を確認できない場合は「不明」とする。

完成レポートは、実行情報と対象、シグナルの説明、ブランチ・ログ別ダッシュボード、`継続すべき点`、`改善すべき点`、次回に試す行動、不明・未分析・失敗・限界の順を基本とする。各所見のタイトル、解釈、提案は、複数タスクへ再利用できる人間のCodex活用行動として表す。個別タスクの出来事は観察事実と根拠例に置き、人間の必要最小限の引用、ログパス・セッションID・行番号、単一セッションまたは横断傾向の別を残す。外部観点ID、資料の明記、ログへの適用が推論であること、適用範囲、不明点は判断に必要な範囲で示し、分析者向けの心得やシグナルの誤判定注意は方法・限界へ短く隔離する。

「次回に試す行動」は、人間がCodexへ与える指示、判断の前にそろえる観点、逸脱時の介入、作業をまたいで続ける習慣のいずれかとして書く。Codex自身の分析・実装手順や、Codex利用に固有でない一般的な開発作業は置かない。

### 同じ3ログでの再分析と旧レポート（REQ-002、REQ-003、REQ-005、REQ-006）

`kaizen/73`、`docs/49`、`env/28` の同じ追跡パスと、可能なら旧レポート記録時と同じハッシュを選び、新設計で再分析する。ハッシュが変わっていた場合は同じ入力とは扱わず、差を記録する。

旧レポートは履歴と旧要求の検証資料として保持する。再分析レポートは別名で保存し、旧レポートを参照する。比較では、ポイント中心の構造、人間の行動だけを主語にした所見、引用、明記・推論・不明・適用範囲、全シグナルの値と導線、次の行動を確認する。旧所見をそのまま移さず、原文と新しい評価観点から再判定し、追加・削除・変更の理由を記録する。

### 検証方針

- REQ-001・REQ-003: 模擬PR情報で全件、未分析、個別選択、再分析、名前衝突、復旧重複、手動採否、取得失敗、不正レポートを確認する。旧レポートを保持して同じキーの新レポートを保存でき、完成対象だけが分析済みになることを確認する。
- REQ-002: 合成会話で、Codexの応答が所見の主語にならず、人間の引用と位置、単一・横断の別、不明を確認する。所見のタイトル・解釈・提案が複数タスクへ再利用でき、個別事象は根拠例になっていること、次回行動が人間の指示・判断・介入・習慣に限られること、分析者向けの心得が所見本文へ混在しないことを確認する。同じ3ログを再分析し、旧レポートとの差を原文に照らす。
- REQ-004: 長い単一発言、境界をまたぐ話題、大量の子結果、失敗、途中変更を試す。代表的大量ログでは対象量、分割値、実行環境、親子の圧縮の観測方法と結果を記録し、観測不能は不明とする。
- REQ-005: 出典、確認日、資料の明記、推論、適用範囲、証拠の種類、限界を形式と実例で確認する。製品固有の推奨、資料間の相違、ログ外の成果が必要な例を確認する。
- REQ-006: 5シグナルを合成会話の手計算値と照合する。意味分類は機械候補とLLM採用を分け、誤検出・判定不能を残す。同じ3ログでシグナルの意味と探索用途、ログ別の正確な件数、率と分母、少数データの扱い、読む入口をMarkdown表で確認し、全体合計が補助であることを確認する。少なくともラリー数の比較グラフがMarkdown表示で崩れず、表の値と一致することを確認する。値だけで所見を作らず、シグナル外の所見も拾えることを確認する。
- Skillの形式、実際の手動起動、利用者選択後の継続、子へのファイル受け渡し、原子的保存、一時ファイル削除を確認する。

### 未決事項

なし。圧縮の観測手段とシグナル閾値は未検証だが、観測不能時の表現と試行後の調整条件を定めており、実装を妨げない。
